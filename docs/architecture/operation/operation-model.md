# Operation Model

## Цель

Определить единую модель выполнения длительных операций лаунчера

Любая операция должна иметь предсказуемый жизненный цикл,
единые точки расширения и возможность безопасного управления
в будущем (Concurrency, Cancellation, Progress)

## Operation

Operation представляет собой высокоуровневый сценарий, который приводит систему из одного
согласованного состояния в другое

Operation может состоять из одной или нескольких LauncherTask

В течение своего жизненного цикла Operation публикует события через EventBus, уведомляя 
остальные подсистемы о начале и завершении выполнения

## Общая структура любой операции

Любая операция должна состоять из одинаковых этапов

 Analyze  - Изучить текущее состояние системы (Проверить существующие файлы)
    ↓
   Plan   - Построить план (DownloadPlan)
    ↓
 Execute  - Выполнить изменения (скачать библиотеки)
    ↓
  Verify  - Убедиться, что результат корректный (проверить SHA-256)
    ↓
 Finalize - Освободить ресурсы, создать отчет, опубликовать события
 
## Инварианты

O-1

Каждая операция имеет одного владельца

O-2

Operation не изменяет состояние системы до завершения стадии Planning

O-3

Любая длительная операция обязана завершиться публикацией результата, даже если произошла ошибка

O-4

Operation никогда не управляет UI напрямую, UI только подписывается на события
