# ADR-0060: Определить пользовательские каталоги конфигурации и данных launcher

## Статус

Accepted

---

## Контекст

На момент принятия решения `LauncherConfigurationResolver` использует `Path.of("")`, если launcher directory не задана
аргументом запуска

В результате расположение `game`, `runtime`, `downloads` и `logs`, создаваемых относительно launcher directory, зависит от рабочей
директории процесса

`PropertiesManifestUriSource` уже умеет читать manifest URI из файла, но расположение этого файла не определено

[ADR-0059](ADR-0059-launcher-manifest-source-boundary.md) закрепляет источник manifest URI до launcher lifecycle, оставляя выбор каталога конфигурации и launcher directory
за пределами решения

Проект различает Windows, Linux и macOS

Необходимо определить пользовательские каталоги по умолчанию без привязки launcher lifecycle к расположению файлов на
конкретной ОС

---

## Решение

`launcher-app` определяет платформенные пользовательские каталоги до создания `LauncherConfiguration`

Каталог конфигурации приложения и launcher directory выполняют разные роли и определяются независимо, даже если по умолчанию
используют один базовый каталог

Файл `launcher.properties` находится в каталоге конфигурации приложения

Если launcher directory не задана явно, используется пользовательский каталог данных приложения для соответствующей ОС

Платформенные расположения по умолчанию

- Windows: каталог конфигурации и каталог данных находятся в отдельной поддиректории приложения внутри LocalAppData
- Linux: каталог конфигурации находится внутри `XDG_CONFIG_HOME`, каталог данных — внутри `XDG_DATA_HOME`;
  при отсутствии этих переменных применяются стандартные пользовательские расположения XDG
- macOS: каталог конфигурации и каталог данных находятся в поддиректории приложения внутри пользовательского `Application Support`

Поддиректория приложения имеет стабильное имя, не зависящее от версии launcher

Явно заданная launcher directory имеет приоритет над каталогом данных по умолчанию

Изменение launcher directory не переносит файл конфигурации приложения

`LauncherConfiguration` получает уже выбранный путь и не определяет платформенные каталоги самостоятельно

`LocalDirectoryProvider` продолжает строить внутренние директории относительно `LauncherConfiguration.launcherDirectory()`

Рабочая директория процесса не используется как неявный fallback для пользовательских данных

---

## Рассмотренные варианты

### Использовать рабочую директорию процесса

Вариант отклонен

Результат зависит от способа запуска приложения и может разместить игровые данные внутри исходного репозитория или
каталога установки

### Разместить все данные Windows в RoamingAppData

Вариант отклонен

Существующая launcher directory содержит не только небольшую конфигурацию, но и игровые файлы, runtime, загрузки и логи,
привязанные к конкретному устройству

### Сразу разделить игровые данные, загрузки, cache и логи по разным системным каталогам

Вариант отложен

Существующий `LocalDirectoryProvider` строит их относительно одной launcher directory

Разделение потребует самостоятельного решения о структуре данных и миграции существующих путей

---

## Последствия

Расположение данных по умолчанию больше не зависит от рабочей директории процесса

Файл конфигурации остается доступен по стабильному пути, даже если пользователь позже выберет другую launcher directory

`launcher-app` получает ответственность за платформенное определение каталогов и проверку этого поведения на разных ОС

Для Windows используется LocalAppData, а не привычный для некоторых launcher RoamingAppData

Сохранение всех внутренних директорий под одной launcher directory остается упрощением: отдельные платформенные каталоги
для cache и логов пока не вводятся

Изменение значения по умолчанию не переносит автоматически данные, ранее созданные относительно рабочей директории

Выбор каталога не создает отсутствующий `launcher.properties` и сам по себе не обеспечивает наличие manifest URI

---

## Не входит в решение

- UI для выбора launcher directory
- Хранение выбранной пользователем launcher directory
- Автоматическое создание файла конфигурации
- Поведение UI при отсутствии или ошибке конфигурации
- Перенос ранее созданных игровых данных
- Разделение cache, логов и загрузок по отдельным платформенным каталогам
- Portable mode и общесистемная конфигурация
