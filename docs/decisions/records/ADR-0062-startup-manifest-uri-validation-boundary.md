# ADR-0062: Определить единую границу проверки manifest URI при startup

## Статус

Accepted

---

## Контекст

На момент принятия решения `LauncherConfigurationResolver` получает manifest URI из локального `keystone.properties` или
явного аргумента запуска

Локальный источник проверяет, что URI является абсолютным HTTP(S) URI с host

Явный аргумент преобразуется через `URI.create`, но не проходит ту же проверку

В результате одинаковое по смыслу значение может быть отклонено при чтении локальной конфигурации и принято при передаче
через аргумент запуска

Ошибка явного URI может обнаружиться после подготовки startup boundary, хотя источник manifest URI определяется до launcher
lifecycle согласно [ADR-0059](ADR-0059-launcher-manifest-source-boundary.md)

[ADR-0061](ADR-0061-presentation-startup-configuration-failure-boundary.md) определяет отображение ошибки локальной конфигурации до приема launch request

Необходимо установить единые требования к manifest URI независимо от его источника и определить, как ошибка явного аргумента
соотносится с существующей startup-моделью

---

## Решение

`launcher-app` проверяет manifest URI до создания `LauncherConfiguration` независимо от того, получен он из локальной конфигурации
или явного аргумента запуска

Для обоих источников допустим абсолютный HTTP(S) URI с host

Ошибки синтаксиса и нарушения этих требований для обоих источников представлены `ManifestUriConfigurationException`

Явный аргумент сохраняет приоритет перед локальным источником согласно [ADR-0059](ADR-0059-launcher-manifest-source-boundary.md)

При некорректном явном URI локальный источник не используется как fallback

Для JavaFX startup такая ошибка приводит к существующему исходу недоступности запуска согласно [ADR-0061](ADR-0061-presentation-startup-configuration-failure-boundary.md)

Окно показывает безопасное сообщение без исходного URI и текста исключения, а launch request не принимается

CLI entrypoint завершает разрешение конфигурации ошибкой до запуска launcher lifecycle

Проверка структуры URI не подтверждает доступность сервера, возможность загрузки или корректность содержимого манифеста

---

## Рассмотренные варианты

### Проверять только локальную конфигурацию

Вариант отклонен

Технический способ передачи manifest URI через аргумент запуска обходил бы требования к тому же входному значению

### При ошибке явного аргумента использовать локальный URI

Вариант отклонен

Такой fallback скрывал бы ошибку явно выбранного источника и мог бы запустить приложение с неожиданной конфигурацией

### Проверять доступность manifest URI во время startup

Вариант отложен

Сетевая доступность и загрузка манифеста относятся к существующему launcher lifecycle, а не к структурной проверке исходной
конфигурации

---

## Последствия

Оба источника manifest URI подчиняются одному контракту до создания `LauncherConfiguration`

Некорректный явный URI больше не переводит JavaFX startup в состояние доступного запуска

Существующая startup-модель применяется не только к ошибке локального файла, но и к некорректному явному manifest URI

Историческое содержание [ADR-0061](ADR-0061-presentation-startup-configuration-failure-boundary.md) при этом не изменяется

CLI сохраняет явный аргумент как технический способ запуска, но отклоняет его некорректное значение раньше

Единая проверка добавляет общую ответственность в `launcher-app`

Источники конфигурации сохраняют ответственность за получение исходного значения

Безопасное сообщение UI не различает источник ошибки, поэтому для выяснения причины пользователь должен проверить
переданный аргумент или локальную конфигурацию вне UI

---

## Не входит в решение

- Проверка доступности сервера и содержимого манифеста во время startup
- Fallback на локальную конфигурацию при ошибке явного аргумента
- Новые источники manifest URI
- Редактирование конфигурации и recovery actions в UI
- Изменение проверки launcher directory и других аргументов запуска
- Изменение `LaunchResult` или presentation launch completion
