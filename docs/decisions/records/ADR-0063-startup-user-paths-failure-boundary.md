# ADR-0063: Определить границу ошибки пользовательских путей при startup

## Статус

Accepted

> Примечание: решение реализовано в итерации `feat(startup): handle user paths resolution failure`

---

## Контекст

На момент принятия решения `LauncherConfigurationResolver` определяет пользовательские пути по умолчанию до создания
`LauncherConfiguration`

[ADR-0060](ADR-0060-launcher-user-directories-boundary.md) закрепляет платформенные каталоги и не допускает неявный fallback в рабочую директорию процесса

Если необходимые данные окружения отсутствуют или некорректны, `LauncherUserPathsResolver` не может определить пути

Такой отказ возникает до приема launch request

`PresentationStartupInitializer` согласно [ADR-0061](ADR-0061-presentation-startup-configuration-failure-boundary.md) обрабатывает ожидаемую ошибку manifest URI, но не различает отказ
определения пользовательских путей

Поскольку `LauncherApplication` подготавливает launch boundary до показа окна, при таком отказе пользователь не получает
контролируемого объяснения недоступности запуска

Кроме того, при одном явном аргументе пользовательские пути определяются до проверки manifest URI

Ошибка путей может скрыть ошибку явно переданного URI, хотя [ADR-0062](ADR-0062-startup-manifest-uri-validation-boundary.md) относит его проверку к startup configuration boundary

Необходимо определить реакцию на ожидаемый отказ пользовательских путей, не превращая любые startup exceptions в ошибку
конфигурации

---

## Решение

`launcher-app` различает ожидаемый отказ определения пользовательских путей и неожиданный сбой startup

Отсутствие или некорректность необходимых платформенных данных для построения путей представляется отдельной
`LauncherUserPathsResolutionException`

Эта ошибка не подменяется `ManifestUriConfigurationException`

Если manifest URI задан явно, он проверяется до определения пользовательских путей по умолчанию

Явно заданная launcher directory сохраняет приоритет

Когда оба аргумента заданы, пользовательские пути по умолчанию не определяются

`launcher-ui` преобразует `LauncherUserPathsResolutionException` в существующий исход `PresentationStartupState.CONFIGURATION_FAILED`

JavaFX window показывается с безопасным сообщением без исходных путей и текста исключения

Launch action недоступен, launch request не принимается, `PresentationLaunchCompletion` не создается

Неожиданные исключения других частей startup не преобразуются в `CONFIGURATION_FAILED`

CLI entrypoint завершает разрешение конфигурации ошибкой до запуска launcher lifecycle и не использует presentation-модель

Невозможность определить пользовательские пути после применения правил [ADR-0060](ADR-0060-launcher-user-directories-boundary.md) не приводит к дополнительному
fallback в рабочую директорию процесса

---

## Рассмотренные варианты

### Перехватывать любые startup exceptions

Вариант отклонен

Общий перехват скрыл бы ошибки реализации и представил их пользователю как ожидаемую ошибку конфигурации

### Использовать рабочую директорию при отказе платформенных путей

Вариант отклонен

Такой fallback нарушил бы границу расположения пользовательских данных, установленную [ADR-0060](ADR-0060-launcher-user-directories-boundary.md)

### Добавить отдельное presentation-состояние для ошибки путей

Вариант отложен

На момент принятия решения ошибка путей не требует отдельного пользовательского действия или сценария восстановления

---

## Последствия

Ожидаемый отказ определения пользовательских путей получает контролируемый исход JavaFX startup

Существующее `CONFIGURATION_FAILED` описывает недоступность исходной конфигурации до приема launch request, не меняя смысл
`PresentationLaunchState.FAILED`

Проверка явно переданного manifest URI не зависит от возможности определять пути по умолчанию

Для отказа пользовательских путей требуется отдельный тип ошибки и тесты границы между `launcher-app` и `launcher-ui`

Без отдельной startup diagnostics безопасное сообщение не раскрывает пользователю конкретное значение окружения, которое
необходимо исправить

Отказ от дополнительного fallback сохраняет предсказуемое расположение данных, но при неисправном окружении запуск с путями
по умолчанию недоступен

---

## Не входит в решение

- Автоматическое создание или перенос пользовательских каталогов
- Fallback в рабочую директорию процесса
- Проверка доступности каталогов после выбора путей
- Обработка некорректной явно заданной launcher directory
- Редактирование путей и recovery actions в UI
- Общая система startup diagnostics
- Перехват всех исключений подготовки presentation launch boundary
- Изменение `LaunchResult` и launcher lifecycle
