# ADR-0064: Определить границу ошибки явно заданной launcher directory при startup

## Статус

Accepted

---

## Контекст

На момент принятия решения `LauncherConfigurationResolver` принимает явно заданную launcher directory вторым аргументом
запуска и преобразует ее через `Path.of`

[ADR-0060](ADR-0060-launcher-user-directories-boundary.md) определяет платформенный каталог данных по умолчанию и не допускает неявный fallback в рабочую директорию процесса

Явный аргумент имеет приоритет перед каталогом по умолчанию

Пустое значение аргумента может привести к построению внутренних директорий относительно рабочей директории процесса

Синтаксически некорректное значение может завершить startup до показа JavaFX window

[ADR-0061](ADR-0061-presentation-startup-configuration-failure-boundary.md) и [ADR-0063](ADR-0063-startup-user-paths-failure-boundary.md) определяет контролируемый исход для ожидаемых ошибок исходной конфигурации, но не охватывают ошибку
явно заданной launcher directory

Необходимо определить границу проверки этого аргумента, не меняя существующее поведение корректных относительных путей и
не преобразуя любые startup exceptions в ошибку конфигурации

---

## Решение

`launcher-app` проверяет явно заданную launcher directory до создания `LauncherConfiguration`

Пустое, состоящее только из пробельных символов или синтаксически некорректное значение отклоняется
как `LauncherDirectoryConfigurationException`

Некорректный явный аргумент не заменяется каталогом данных по умолчанию

Непустой синтаксически корректный относительный путь сохраняется как допустимый явный аргумент

Проверка не подтверждает существование каталога, права доступа или возможность записи в него

`launcher-ui` преобразует `LauncherDirectoryConfigurationException` в существующий `PresentationStartupState.CONFIGURATION_FAILED`

JavaFX window показывается с безопасным сообщением без исходного пути и текста исключения

Launch action недоступен, launch request не принимается и `PresentationLaunchCompletion` не создается

CLI entrypoint завершает разрешение конфигурации ошибкой до запуска launcher lifecycle и не использует presentation-модель

Другие неожиданные исключения startup не преобразуются в `CONFIGURATION_FAILED`

---

## Рассмотренные варианты

### Считать пустой аргумент отсутствующим

Вариант отклонен

Такой fallback скрывал бы ошибку явно переданного значения и мог бы изменить выбранное расположение данных

### Требовать абсолютный путь для явной launcher directory

Вариант отклонен

Существующее поведение допускает непустой относительный путь как явный технический аргумент

Изменение этого контракта требует отдельного подтвержденного сценария

### Перехватывать любые ошибки построения путей при startup

Вариант отклонен

Общий перехват смешал бы ошибку входного аргумента с неожиданными сбоями других частей startup

---

## Последствия

Некорректный явный аргумент launcher directory получает контролируемый исход JavaFX startup

Пустое значение больше не приводит к размещению данных относительно рабочей директории процесса

Платформенный каталог по умолчанию используется только при отсутствии явного аргумента

Корректные относительные пути остаются совместимыми с существующим поведением аргумента

Для новой границы требуется отдельный тип ошибки и тесты в `launcher-app` и `launcher-ui`

Без recovery action пользователь исправляет аргумент вне открытого окна и повторно запускает приложение

---

## Не входит в решение

- Проверка существования каталога и прав доступа
- Автоматическое создание или перенос данных
- Требование абсолютного пути для явного аргумента
- Выбор или редактирование launcher directory в UI
- Fallback при ошибке явно заданного пути
- Общая система startup diagnostics
- Перехват всех исключений подготовки presentation launch boundary
- Изменение `LaunchResult` и launcher lifecycle
