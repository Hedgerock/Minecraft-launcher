# ADR-0065: Определить границу повторной подготовки локальной startup-конфигурации

## Статус

Accepted

---

## Контекст

На момент принятия решения `LauncherApplication` разрешает исходную конфигурацию и подготавливает `PresentationLaunchBoundary`
при открытии окна

При ожидаемой ошибке конфигурации окно остается доступным, а launch action блокируется согласно
[ADR-0061](ADR-0061-presentation-startup-configuration-failure-boundary.md)

После исправления локального `keystone.properties` пользователь должен перезапустить приложение, поскольку повторная подготовка
конфигурации в открытом окне не предусмотрена

`PresentationStartupState.CONFIGURATION_FAILED` объединяет ошибки локального источника, явно заданных аргументов и определения
пользовательских путей

Однако одинаковый presentation-исход не означает, что все эти причины можно исправить одним действием в UI

Необходимо определить границу повторной подготовки локальной конфигурации, не превращая ее в повтор launch request и не
изменяя приоритет явно заданных аргументов

---

## Решение

`launcher-ui` предоставляет отдельное действие повторной подготовки startup-конфигурации при ожидаемой ошибке локального
источника manifest URI

Действие доступно, когда manifest URI должен быть получен из локального `keystone.properties`, но этот источник не удалось
прочитать или его значение не прошло проверку

Перед повторной попыткой пользователь исправляет локальную конфигурацию вне приложения

`launcher-app` сохраняет ответственность за чтение и проверку конфигурации, построение `LauncherConfiguration` и подготовку
application boundary

`launcher-ui` не читает `keystone.properties` напрямую и не преобразует его содержимое в `LauncherConfiguration`

При повторной попытке используется тот же порядок выбора источников и та же проверка manifest URI, что и при первоначальном
startup

До успешного завершения повторной подготовки launch action остается недоступен

При повторной ожидаемой ошибке локальной конфигурации UI сохраняет контролируемый исход недоступности запуска

При успешной подготовке UI получает доступную `PresentationLaunchBoundary` и может принимать обычный launch request

Повторная подготовка не создает `LaunchResult` или `PresentationLaunchCompletion` и не переводит `PresentationLaunchStateMachine`
в состояние неуспешного запуска

Ошибочный явно заданный аргумент не заменяется локальной конфигурацией и не исправляется этим действием

Ошибка определения пользовательских путей также не считается ошибкой содержимого `keystone.properties`

Неожиданные сбои подготовки boundary не преобразуются в ожидаемую ошибку локальной конфигурации

---

## Рассмотренные варианты

### Считать повторную подготовку повтором launch request

Вариант отклонен

Launch request может быть принят только после успешной подготовки исходной конфигурации и presentation boundary

### Повторять подготовку для любого CONFIGURATION_FAILED

Вариант отклонен

Общее presentation-состояние не сохраняет различие между локальным файлом, явным аргументом и пользовательскими путями

Повторение без учета источника не даст пользователю понятного действия и может скрыть ошибку явно заданного значения

### Сразу редактировать manifest URI на launch screen

Вариант отложен

[ADR-0059](ADR-0059-launcher-manifest-source-boundary.md) не делает ввод произвольного URI основным действием запуска

Отдельный сценарий настройки источника потребует решения о пользовательском взаимодействии и доверии к манифесту

---

## Последствия

Ожидаемая ошибка локальной конфигурации перестает требовать перезапуска приложения после исправления файла

Startup boundary должна сохранять достаточно информации, чтобы отличить ошибку локального источника от других причин
`CONFIGURATION_FAILED`, не раскрывая исходное исключение в UI

Повторная подготовка остается отдельной от launcher lifecycle и не меняет смысл состояний принятого launch request

Понадобятся тесты повторной ошибки и успешной подготовки после исправления локального файла

Компромисс первого шага состоит в том, что пользователь по-прежнему исправляет `keystone.properties` вне приложения

Решение не делает launcher полностью самостоятельным пользовательским продуктом и не определяет доверенный источник
манифеста

---

## Не входит в решение

- Создание и редактирование `keystone.properties` через UI
- Ввод произвольного manifest URI на launch screen
- Выбор профиля или версии игры
- Изменение приоритета явно заданных аргументов
- Fallback на локальную конфигурацию при ошибке явного аргумента
- Восстановление пользовательских путей
- Автоматическое наблюдение за изменением файла
- Подпись манифеста и общая модель доверия к его источнику
- Изменение `LaunchResult` и launcher lifecycle
