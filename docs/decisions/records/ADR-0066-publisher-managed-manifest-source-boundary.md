# ADR-0066: Определить границу управляемого источника манифеста

## Статус

Accepted

---

## Контекст

На момент принятия решения `launcher-app` получает manifest URI из явного аргумента или локального
`keystone.properties`

Оба способа позволяют указать произвольный HTTP(S) URI, а запуск без явного аргумента требует предварительной подготовки
локального файла

Такая конфигурация подходит для технического запуска, но не определяет источник манифеста для обычного пользовательского
сценария

Для пользовательского запуска необходимо определить владельца публикации манифеста, не перенося выбор источника в `launcher-core`
или на основной экран UI

---

## Решение

Обычный пользовательский запуск получает манифест из источника, контролируемого владельцем продукта

Пользователь не должен вручную вводить manifest URI или создавать `keystone.properties` для обычного запуска

`launcher-app` определяет источник manifest URI до создания `LauncherConfiguration`

`launcher-api` сохраняет ответственность за загрузку и преобразование манифеста, а `launcher-core` использует подготовленный
результат без выбора источника

Явный manifest URI и `keystone.properties` сохраняются как способы технического запуска и проверки приложения

При недоступности управляемого источника обычный запуск не переключается автоматически на произвольный URI из локальной
конфигурации

Выбор управляемого источника сам по себе не подтверждает подлинность полученного манифеста и не заменяет отдельную политику
доверия к его содержимому и ресурсам

---

## Рассмотренные варианты

### Требовать `keystone.properties` для обычного запуска

Вариант отклонен

Обязательное создание файла переносит техническую настройку источника на пользователя и препятствует запуску без предварительных
действий

### Предоставить ввод произвольного URI на основном экране

Вариант отклонен для обычного запуска

Источник манифеста не должен становиться обязательным пользовательским выбором согласно [ADR-0059](ADR-0059-launcher-manifest-source-boundary.md)

### Сразу выбрать способ подтверждения подлинности манифеста

Вариант отложен

Владелец публикации определен, но конкретный способ доставки, проверки подлинности и управления ключами
требует отдельного решения

---

## Последствия

Для обычного пользовательского запуска потребуется источник конфигурации, не зависящий от ручного создания
`keystone.properties`

Существующие способы технического запуска остаются доступными и не получают статус доверенного источника только из-за способа
передачи URI

Границу обычного и технического запуска потребуется явно отразить в реализации и тестах

Отказ от автоматического fallback ограничивает доступность запуска при ошибке управляемого источника, но не скрывает ее
подстановкой другого манифеста

Текущий startup flow остается техническим сценарием до реализации управляемого источника и отдельной политики доверия

---

## Не входит в решение

- Конкретный адрес, способ размещения и обновления манифеста
- Подпись манифеста и управление ключами
- Политика допустимых источников файлов из манифеста
- Создание и редактирование `keystone.properties` в UI
- Пользовательские настройки расположения файлов и параметров памяти
- Изменение launcher lifecycle и `LaunchResult`
