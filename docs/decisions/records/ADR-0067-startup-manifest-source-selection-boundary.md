# ADR-0067: Определить границу выбора источника манифеста при startup

## Статус

Accepted

---

## Контекст

На момент принятия решения `LauncherConfigurationResolver` получает manifest URI из явного аргумента или, при его отсутствии,
из `keystone.properties`

Наличие локального файла не требует явного выбора технического источника

[ADR-0066](ADR-0066-publisher-managed-manifest-source-boundary.md) определяет управляемый владельцем продукта источник для обычного пользовательского запуска
без ручной настройки manifest URI

Существующий неявный выбор `keystone.properties` не позволяет отличить такой запуск от технического сценария

Необходимо определить порядок выбора источника до создания `LauncherConfiguration`, сохранив технические способы запуска и
исключив неявную подстановку другого манифеста

---

## Решение

Если источник манифеста не выбран явно, `launcher-app` использует управляемый источник для обычного пользовательского запуска

Явно заданный manifest URI выбирает технический запуск с этим URI

Для использования `keystone.properties` как технического источника требуется отдельный явный выбор

Наличие `keystone.properties` само по себе не меняет источник обычного запуска

При ошибке управляемого источника `launcher-app` не переходит автоматически к `keystone.properties` или другому URI

Выбранный manifest URI проходит общую структурную проверку до создания `LauncherConfiguration`

Выбор источника остается ответственностью `launcher-app`

`launcher-ui` не выбирает URI на основном экране, а `launcher-core` не определяет политику выбора источника

Явный выбор технического источника не придает полученному манифесту статус доверенного

---

## Рассмотренные варианты

### Сохранить `keystone.properties` неявным источником

Вариант отклонен для обычного запуска

Наличие локального файла продолжило бы определять источник манифеста без явного выбора технического сценария

### Использовать локальный файл при ошибке управляемого источника

Вариант отклонен

Такой fallback скрыл бы ошибку выбранного источника и мог бы запустить приложение с другим манифестом

### Удалить технические способы запуска

Вариант отклонен

Явный URI и локальный файл остаются полезными для разработки, интеграционных проверок и диагностики

---

## Последствия

Запуск без явного выбора источника перестанет читать `keystone.properties` после реализации решения

Для технического запуска через локальный файл потребуется явный способ его включения

Тесты startup-конфигурации должны различать управляемый источник, явный URI и явно выбранный локальный файл

Ошибки выбора и подготовки источника остаются ошибками startup-конфигурации до принятия launch request

Повторная подготовка после исправления `keystone.properties` сохраняет смысл только для явно выбранного локального источника
согласно [ADR-0065](ADR-0065-presentation-startup-configuration-retry-boundary.md)

Обычный запуск не сможет завершить startup-подготовку, пока управляемый источник не предоставлен; технический источник не
используется как скрытый обход этого ограничения

Решение не подтверждает подлинность манифеста и не определяет политику ресурсов

---

## Не входит в решение

- Конкретный URI и способ доставки управляемого источника
- Синтаксис явного включения `keystone.properties`
- Подпись манифеста и управление ключами
- Политика допустимых источников файлов из манифеста
- Настройки расположения файлов и параметров памяти
- Изменение launcher lifecycle и `LaunchResult`
