# ADR-0068: Определить поставку URI управляемого манифеста в составе приложения

## Статус

Accepted

---

## Контекст

На момент принятия решения [ADR-0066](ADR-0066-publisher-managed-manifest-source-boundary.md) определяет управляемый владельцем продукта источник манифеста для обычного
пользовательского запуска

[ADR-0067](ADR-0067-startup-manifest-source-selection-boundary.md) отделяет этот запуск от технических способов передачи manifest URI

Однако приложение пока не содержит URI управляемого источника, а запуск без явного выбора продолжает читать пользовательский
`keystone.properties`

Обычный запуск не должен требовать создания технического файла пользователем

Необходимо определить, как приложение получает URI управляемого источника без переноса этой конфигурации в пользовательский
каталог

---

## Решение

URI управляемого манифеста поставляется в `.properties`-ресурсе в составе приложения

`launcher-app` читает ресурс из приложения и использует его для обычного запуска до создания `LauncherConfiguration`

Ресурс не копируется в пользовательский каталог и не используется как файл пользовательских настроек

Полученное значение проходит общую структурную проверку manifest URI

При обычном запуске отсутствие ресурса или некорректный URI приводит к ошибке startup-конфигурации без перехода к
техническому источнику

Технические способы запуска с явным URI и `--local-config` не требуют изменения упакованного ресурса

Поставка URI вместе с приложением определяет источник конфигурации, но сама по себе не подтверждает подлинность загруженного
манифеста

---

## Рассмотренные варианты

### Копировать исходную конфигурацию в пользовательский каталог

Вариант отклонен

Изменяемая пользовательская копия перестала бы быть управляемым источником конфигурации для обычного запуска

### Получать адрес через отдельный удаленный сервис

Вариант отложен

Дополнительная точка обнаружения источника пока не требуется для одного управляемого manifest URI

---

## Последствия

Обычный запуск сможет получить manifest URI без действий пользователя после добавления действительного значения
в поставляемый ресурс

Изменение самого URI потребует новой сборки приложения

Содержимое манифеста может обновляться по прежнему URI без изменения упакованного ресурса

Отсутствие или ошибка ресурса не скрываются переходом к техническому источнику

Потребуются тесты корректного, отсутствующего и некорректного значения ресурса, а также выбора источника при startup

Решение не устанавливает доверие к сетевому ответу и не определяет политику источников файлов, указанных в манифесте

---

## Не входит в решение

- Конкретный адрес и место размещения манифеста
- Подпись манифеста и управление ключами
- Формат пользовательских настроек и поддержка YAML
- Копирование служебного ресурса в пользовательский каталог
- Автоматическое обновление приложения
- Изменение launcher lifecycle и `LaunchResult`
