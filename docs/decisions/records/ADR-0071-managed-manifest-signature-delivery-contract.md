# ADR-0071: Определить контракт доставки подписи управляемого манифеста

## Статус

Accepted

---

## Контекст

На момент принятия решения [ADR-0070](ADR-0070-managed-manifest-authenticity-boundary.md) требует проверить подпись исходных байтов управляемого манифеста до преобразования
JSON

`launcher-api` уже предоставляет байты ответа, но алгоритм подписи, способ ее получения и формат доверенного публичного ключа
не определены

Без единого контракта публикация манифеста и его проверка в launcher могут использовать несовместимые представления данных

Необходимо зафиксировать минимальный контракт доставки подписи, не вводя на этом шаге инфраструктуру смены ключей и защиты
от повторного предъявления старого манифеста

---

## Решение

Для подписи исходных байтов управляемого манифеста используется Ed25519

Подпись поставляется отдельным бинарным ресурсом и содержит байты подписи без текстового кодирования и дополнительных полей

В упакованном `.properties`-ресурсе управляемого источника вместе с `manifest.uri` задается отдельный `manifest.signature.uri`

Оба URI являются абсолютными HTTPS URI и проходят проверку до загрузки управляемого манифеста

Перенаправления при загрузке манифеста и подписи отклоняются

URI подписи не выводится из имени манифеста и не принимается из загруженного содержимого

Доверенный публичный ключ Ed25519 поставляется отдельным ресурсом приложения в формате `SubjectPublicKeyInfo` с DER-кодированием

Алгоритм и доверенный ключ не выбираются по данным сетевого ответа

`launcher-app` передает параметры управляемого источника при сборке загрузки манифеста, не добавляя их в `LauncherConfiguration`
для `launcher-core`

`launcher-api` получает байты манифеста и подписи и проверяет подпись до декодирования JSON и создания `ManifestLoadResult`

При отсутствии или некорректности упакованных URI и доверенного ключа подготовка управляемого источника завершается ошибкой

Отсутствие подписи, ошибка ее получения или неуспешная проверка завершает загрузку манифеста ошибкой без перехода к техническому
источнику

Явный manifest URI и `--local-config` не используют упакованные URI подписи и доверенный ключ управляемого источника

---

## Рассмотренные варианты

### Передавать подпись в HTTP-заголовке ответа манифеста

Вариант отклонен для выбранного контракта

Один ответ позволил бы получать содержимое и подпись вместе, но потребовал бы передачи заголовков через существующую HTTP-границу
и связал бы контракт подписи с форматом ответа сервера

### Выводить URI подписи из manifest URI

Вариант отклонен

Неявное правило построения URI связывало бы размещение подписи с формой адреса манифеста и усложняло бы изменение схемы
публикации

### Сразу ввести metadata с версиями и несколькими ключами

Вариант отложен

Смена и отзыв ключей, а также защита от предъявления старой подписанной версии требуют отдельной политики публикации и
проверки

---

## Последствия

Упакованная конфигурация управляемого источника будет содержать два URI вместо одного

Для проверки потребуется получить два сетевых ресурса

Если при обновлении публикации манифест и подпись окажутся от разных версий, загрузка завершится ошибкой

Фиксированный доверенный ключ потребует новой поставки приложения при его замене до появления отдельной политики смены ключей

Публикация должна подписывать ровно те байты манифеста, которые получает launcher для проверки, без промежуточного преобразования
JSON

Успешная проверка подписи подтверждает соответствие содержимого доверенному ключу, но сама по себе не определяет свежесть
манифеста

Технические способы запуска сохраняют прежнее поведение и не получают статус доверенного управляемого источника

---

## Не входит в решение

- Генерация, хранение, смена и отзыв ключей публикации
- Защита от предъявления старого корректно подписанного манифеста
- Конкретные значения URI и инфраструктура публикации
- Политика допустимых URI ресурсов из манифеста
- Изменение launcher lifecycle и пользовательского интерфейса
