# ADR-0073: Определить допустимые URI ресурсов управляемого манифеста

## Статус

Accepted

---

## Контекст

На момент принятия решения [ADR-0070](ADR-0070-managed-manifest-authenticity-boundary.md) требует проверки подписи исходных
байтов управляемого манифеста до преобразования JSON

[ADR-0071](ADR-0071-managed-manifest-signature-delivery-contract.md) ограничивает URI самого управляемого манифеста и его
подписи абсолютными HTTPS URI

Эти ограничения не распространяются на значения `url` загружаемых ресурсов внутри манифеста

`ManifestResources` объединяет файлы, assets и выбранные library artifacts в общий набор `ResourceEntry`

Модели ресурсов требуют непустой `url`, но не определяют допустимую схему и источник загрузки

При восстановлении ресурса downloader открывает переданный URL без отдельной политики для управляемого источника

Необходимо определить условия принятия URI ресурсов до передачи управляемого манифеста в launcher lifecycle и исключить обход
этих условий при фактической загрузке

---

## Решение

Для источника `MANAGED` каждый ресурс, выбранный для verification/download lifecycle, должен содержать абсолютный HTTPS URI
с host

Относительные URI, другие схемы, сведения пользователя и fragment в URI управляемого ресурса не допускаются

Проверка распространяется на `Manifest.files`, `Manifest.assetsIndex` и выбранные library и native artifacts, представленные
через `ManifestResources`

Метадата library artifacts, не выбранных для данного runtime environment, не входит в проверяемый набор ресурсов

Проверка выполняется после успешной проверки подписи и преобразования манифеста, но до передачи `ManifestLoadResult` в
`launcher-core`

Некорректный URI выбранного ресурса завершает загрузку управляемого манифеста ошибкой, даже если соответствующий локальный
файл уже прошёл verification и не требует скачивания

Автоматический переход к техническому источнику при такой ошибке не выполняется

Фактическая загрузка управляемого ресурса не должна следовать HTTP-перенаправлению на другой URI

`launcher-app` выбирает политику для управляемого источника при сборке manifest loading и resource download boundaries

`launcher-api` проверяет URI ресурсов при принятии управляемого манифеста

`launcher-downloader` соблюдает выбранную transport policy при получении ресурсов

`launcher-core`, `ManifestResources` и базовые модели `ResourceEntry` не получают зависимость от `ManifestSourceKind`

Явный manifest URI и `--local-config` остаются техническими режимами и не получают политику управляемого источника неявно

URI ресурсов не обязаны иметь тот же host, что и управляемый манифест

---

## Рассмотренные варианты

### Ограничить ресурсы host управляемого манифеста

Вариант отложен

Манифест и загружаемые файлы могут размещаться на разных источниках

Допустимый набор host следует определить после выбора действительных источников публикации ресурсов

### Разрешить относительные URI и разрешать их относительно URI манифеста

Вариант отложен

Такое правило связало бы размещение ресурсов с адресом манифеста и потребовало бы отдельной семантики разрешения URI

### Проверять URI только непосредственно перед скачиванием

Вариант отклонен для управляемого источника

Некорректная метадата оставалась бы принятой, если локальный файл уже валиден и скачивание не требуется

### Применить ограничения управляемого источника ко всем режимам

Вариант отклонен

Технические режимы имеют отдельную границу доверия и не должны менять поведение неявно

---

## Последствия

Управляемый манифест с неподходящим URI выбранного ресурса завершит загрузку до начала verification/download lifecycle

Для загрузки управляемых ресурсов потребуется transport behavior, явно отклоняющее перенаправления

Существующий способ открытия URL не подтверждает соблюдение этой политики и должен быть пересмотрен при реализации решения

Разрешение разных HTTPS host сохраняет возможность отдельного размещения манифеста и ресурсов, но не ограничивает запросы
заранее известным набором источников

До пользовательского выпуска с действительными внешними ресурсами необходимо повторно оценить необходимость host allowlist
и ограничений для внутренних сетевых адресов

Проверка URI не заменяет проверку размера и SHA-256 загруженного локального файла

Технические режимы сохраняют прежнее поведение

---

## Не входит в решение

- Конкретные host и URI публикуемых ресурсов
- Host allowlist и политика допустимых сетевых адресов
- Поддержка относительных URI ресурсов
- Retry, resume и cancellation загрузки
- Изменение правил локального `ResourceEntry.path`
- Смена и отзыв ключей подписи манифеста
- Изменение JSON-структуры манифеста
