# ADR-0074: Определить границу локальной записи ресурсов

## Статус

Accepted

> Примечание: решение реализовано в итерациях
> `feat(storage): resolve local write targets within trusted root`
> `feat(downloader): validate local resource write targets`
> `feat(storage): prepare directory targets within trusted root`
> `feat(natives): validate native extraction write targets`

---

## Контекст

На момент принятия решения [ADR-0016](ADR-0016-resource-path-safety.md) определяет лексическую проверку `ResourceEntry.path`
относительно игровой директории

`ResourceSetPlanner` подготавливает нормализованные локальные назначения без обращения к файловой системе

При загрузке ресурсов `DefaultFileDownloader` создает родительские каталоги и временный файл, затем перемещает его в целевое
назначение

При распаковке native artifacts `DefaultNativeExtractionService` создает каталоги и записывает archive entries в директорию
natives

Нормализация пути не определяет фактическое расположение уже существующих компонентов файловой системы

Ссылка или другое перенаправление в промежуточном компоненте назначения может привести к записи за пределами ожидаемого
каталога

Необходимо определить проверку локального назначения непосредственно на границе записи, не смешивая файловый доступ с
pure path policy в `launcher-core`

---

## Решение

Загрузка ресурсов и распаковка native artifacts должны выполнять проверку назначения относительно доверенного корневого
каталога перед локальной записью

Для загрузки ресурсов таким корнем является игровая директория, предоставленная `DirectoryProvider`

Для распаковки native artifacts таким корнем является целевая директория из `NativeExtractionPlan`

Размещение самого доверенного корня определяется существующей конфигурацией launcher и не выбирается значениями manifest
metadata или archive entry

Наличие символической ссылки ниже доверенного корня само по себе не является причиной ошибки

Перед записью adapter проверяет фактическое расположение родительского каталога назначения с учетом существующих ссылок

Если каталог остается внутри фактического расположения доверенного корня, запись допускается

Если каталог выходит за пределы корня или его расположение нельзя подтвердить, операция завершается ошибкой до записи

Проверка применяется только к назначениям, в которые операция действительно будет записывать данные

Отсутствие еще не созданного корневого или родительского каталога само по себе не является ошибкой

Adapter подготавливает необходимые каталоги в существующем flow и проверяет фактическое назначение перед записью

Проверка выполняется на adapter-level границе подготовки назначения и не должна ограничиваться моментом построения
`ResourceSetPlan` или `NativeExtractionPlan`

Контракт записи должен сохранить сведения о доверенном корне до выполнения файловой операции

Одного целевого `Path` без контекста корня недостаточно для проверки этой границы

`SafeResourcePathResolver` продолжает выполнять лексическую проверку и не получает доступ к файловой системе

Проверка применяется независимо от режима источника манифеста

При допустимом назначении существующие обычные файлы могут заменяться согласно текущей политике загрузки и
[ADR-0028](ADR-0028-native-extraction-output-policy.md)

Проверка archive entry на выход за директорию natives остается обязательной и не заменяется новой границей

---

## Рассмотренные варианты

### Считать нормализованный путь достаточной проверкой

Вариант отклонен

Нормализация не учитывает уже существующие компоненты файловой системы, через которые может проходить запись

### Запретить любые ссылки ниже доверенного корня

Вариант отклонен

Ссылка на каталог, фактическое расположение которого остается внутри доверенного корня, не выводит запись за его пределы

Безусловный запрет мог бы нарушить допустимую пользовательскую организацию локальных файлов

### Проверять назначение только при построении плана

Вариант отклонен

Между построением плана и записью состояние локальных каталогов может измениться

Кроме того, `ResourceSetPlanner` должен оставаться pure policy без файлового доступа

### Сразу гарантировать отсутствие гонок при конкурентном изменении каталогов

Вариант отложен

Такая гарантия требует операций относительно устойчиво открытых каталогов и зависит от возможностей
файловой системы

Ее нельзя считать переносимым свойством обычной последовательности проверки `Path` и последующей записи

---

## Последствия

`launcher-downloader` и `launcher-natives` должны учитывать фактическое состояние локального назначения перед записью

Граница загрузки должна получить контекст игровой директории вместе с целевым назначением

Ссылка на каталог внутри доверенного корня не отклоняется только из-за своего типа

Наличие ссылки само по себе не блокирует launcher-lifecycle

Попытка записи за пределы доверенного корня завершает соответствующую операцию ошибкой

Ошибка остается в существующем failure flow соответствующего adapter и не добавляет файловую политику в `launcher-core`

Решение снижает риск записи через уже существующие перенаправления, но не обещает защиту от локального процесса, который
конкурентно меняет компоненты пути во время операции

Особенности распознавания перенаправлений на поддерживаемых файловых системах должны быть подтверждены при реализации и
тестировании

---

## Не входит в решение

- Sandbox на уровне ОС
- Гарантия race-free записи при конкурентной подмене каталогов
- Политика чтения ресурсов через символические ссылки
- Изменение формата `ResourceEntry.path` и archive entry names
- Изменение URI и transport policy загрузки
- Очистка уже существующих ссылок или каталогов
- Версионирование директории natives
- Сохранение символической ссылки при замене существующего целевого файла
