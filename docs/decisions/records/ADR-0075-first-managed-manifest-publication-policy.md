# ADR-0075: Определить политику первой публикации управляемого манифеста

## Статус

Accepted

---

## Контекст

На момент принятия решения [ADR-0072](ADR-0072-managed-manifest-publication-boundary.md) определяет ответственность
издателя за подготовку и проверку подписанного управляемого манифеста

[ADR-0071](ADR-0071-managed-manifest-signature-delivery-contract.md) требует публиковать манифест и его бинарную подпись как
отдельные ресурсы

Действительные URI и доверенный публичный ключ пока не поставляются вместе с приложением

При изменении двух ресурсов по постоянным URI launcher может получить манифест и подпись от разных публикаций

Для первой публикации необходимо определить способ размещения пары, не вводя преждевременно механизм обновления манифеста
для уже установленного приложения

---

## Решение

Первая публикация управляемого манифеста использует два версионных URI: для манифеста и его отдельной подписи

Оба URI указывают на одну публикацию и поставляются вместе с приложением согласно [ADR-0071](ADR-0071-managed-manifest-signature-delivery-contract.md)

После подтверждения публикации содержимое обоих URI не изменяется; исправление или новая версия получает новую пару URI

Издатель подписывает окончательные байты манифеста и публикует их без последующего преобразования

До включения URI и доверенного публичного ключа в пользовательскую сборку издатель получает оба ресурса по их опубликованным
URI и проверяет подпись полученных байтов ключом, предназначенным для этой сборки

Отсутствие любого ресурса, перенаправление или неуспешная проверка подписи не позволяют считать публикацию готовой

Новая публикация получает новые URI; уже поставленные приложению URI не перенаправляются на новую пару

Изменение URI или доверенного публичного ключа для установленного приложения требует новой поставки приложения до принятия
отдельного механизма обновления

Это решение определяет только первую публикацию подписанной пары и само по себе не объявляет обычный пользовательский запуск
готовым

---

## Рассмотренные варианты

### Обновлять манифест и подпись по постоянным URI

Вариант отложен

Раздельная замена ресурсов может временно предоставить launcher несогласованную пару

Для обновления без такого промежутка потребуется отдельная политика публикации и проверки

### Получать URI актуальной версии из удалённых метаданных

Вариант отложен

Дополнительный источник метаданных создал бы новую границу доверия, которая не нужна для первой публикации

---

## Последствия

Первая опубликованная пара не изменяется после выпуска

Launcher не получает несогласованную пару из-за последовательной замены содержимого по тем же URI

Новая версия манифеста не станет доступна уже установленному приложению автоматически

Недоступность опубликованной пары завершит загрузку управляемого манифеста ошибкой без перехода к техническому источнику

Проверка подписи подтверждает соответствие опубликованных байтов доверенному ключу, но не решает вопросы отзыва ключа
и предъявления старой корректно подписанной публикации

Перед обычным пользовательским запуском потребуется отдельно оценить действительные источники ресурсов манифеста и открытые
сетевые ограничения

---

## Не входит в решение

- Выбор хостинга и конкретных значений URI
- Инструмент подписания и хранение закрытого ключа
- Обновление манифеста для уже установленного приложения
- Смена и отзыв ключей
- Защита от предъявления старой корректно подписанной публикации
- Политика допустимых host и внутренних сетевых адресов
- Автоматическое обновление launcher
