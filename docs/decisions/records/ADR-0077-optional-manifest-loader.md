# ADR-0077: Определить семантику отсутствующего загрузчика в манифесте

## Статус

Accepted

---

## Контекст

На момент принятия решения manifest JSON требует `loader`, а преобразование манифеста безусловно создаёт `LoaderInfo`

Эта модель подходит для сборки с загрузчиком, но не позволяет описать сборку без него без фиктивных значений
`type` и `version`

Для подготовки первого vanilla-сценария необходимо отделить отсутствие загрузчика от неполных или ошибочных данных о
существующем загрузчике

Решение касается представления manifest metadata и не определяет готовность всего launch flow к запуску vanilla Minecraft

---

## Решение

Отсутствующий `loader` в manifest JSON означает, что манифест не объявляет отдельный загрузчик

Поле `loader` может быть опущено или иметь значение `null`; оба варианта обозначают отсутствие загрузчика

Если объект `loader` присутствует, его `type` и `version` остаются обязательными и непустыми

Manifest JSON mapping сохраняет различие между отсутствующим загрузчиком и корректным `LoaderInfo`

Доменная модель `Manifest` допускает отсутствие `LoaderInfo` как осмысленное состояние

Фиктивный `LoaderInfo` с типом `vanilla` или версией из `minecraftVersion` не создаётся

`minecraftVersion` остаётся самостоятельной метадатой версии игры и не заменяет версию загрузчика

---

## Рассмотренные варианты

### Представлять vanilla через `LoaderInfo` с типом `vanilla`

Вариант отклонен

Такое значение описывало бы не существующий загрузчик, а его отсутствие, смешивая два разных состояния модели

### Оставить `loader` обязательным для всех манифестов

Вариант отклонен

Это сохраняет текущее ограничение и не позволяет описать сборку без загрузчика без фиктивной метадаты

---

## Последствия

Существующие манифесты с корректным `loader` сохраняют прежнюю семантику

Manifest JSON mapping и его тесты должны различать отсутствие загрузчика, корректный объект загрузчика и неполный объект
загрузчика

Потребителям `Manifest.loader` потребуется учитывать отсутствие значения; это дополнительная развилка в обмен на точное
представление данных

Решение устраняет препятствие в модели манифеста, но не подтверждает готовность загрузки ресурсов и команды запуска для
реальной vanilla-версии

---

## Не входит в решение

- Полная совместимость с форматом официальных Minecraft version manifests
- Получение client, libraries и assets для конкретной vanilla-версии
- Изменения правил построения launch command
- Authentication flow
- Изменение проверки подписи управляемого манифеста
- Строгие переходы состояния launcher lifecycle
