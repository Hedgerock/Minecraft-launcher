# ADR-0079: Определить границу Minecraft asset index для запуска игры

## Статус

Accepted

---

## Контекст

На момент принятия решения [ADR-0049](ADR-0049-assets-index-flow-boundary.md) выделяет assets в отдельную часть manifest
model и подключает их к verification/download flow через `ManifestResources`

`AssetsIndex` описывает проверяемые ресурсы assets, но не содержит идентификатор и физическую метадату файла индекса

Для первого воспроизводимого технического запуска Minecraft требуется разместить файл индекса вместе с asset objects и
передать игре директорию assets и идентификатор индекса

Существующий `DirectoryProvider` определяет директорию assets, однако launch variables не предоставляют значения `${assets_root}`
и `${assets_index_name}`

Необходимо связать файл индекса, его идентификатор и аргументы запуска, сохранив существующую границу восстановления ресурсов

---

## Решение

`AssetsIndex` остаётся manifest-specific источником данных об assets

При объявлении Minecraft asset index модель содержит его идентификатор и физическую метадату файла индекса

Идентификатор должен быть непустым и безопасным для использования как имя индекса

Идентификатор и файл индекса объявляются вместе; путь файла — `assets/indexes/<идентификатор>.json` относительно игровой
директории и согласован с директорией `assets`, предоставляемой `DirectoryProvider`

Asset objects продолжают описываться отдельными `AssetEntry` с явными путями и физической метадатой

Файл индекса и объявленные asset objects преобразуются в `ResourceEntry` через `ManifestResources` и проходят существующий
verification/download flow

`DirectoryProvider` остаётся источником пути для `${assets_root}`

Объявленный в `AssetsIndex` идентификатор становится источником значения `${assets_index_name}`

`LaunchInfo.gameArgs` определяет, нужны ли эти аргументы конкретной сборке

`GameLaunchPlanBuilder` не добавляет Minecraft-specific аргументы самостоятельно

Если launch arguments требуют `${assets_index_name}`, а идентификатор индекса не объявлен, построение плана завершается
ошибкой до запуска игрового процесса

Манифесты без объявленного индекса сохраняют прежнее поведение, если их launch arguments не требуют его идентификатор

`LauncherEngine` не разбирает файл индекса и не получает новую operation для assets

---

## Рассмотренные варианты

### Описывать файл индекса в `Manifest.files`, а идентификатор в `LaunchInfo`

Вариант отклонен

Физическая метадата и идентификатор одного индекса оказались бы разделены между разными частями манифеста

### Разбирать загруженный файл индекса внутри launcher и создавать из него список ресурсов

Вариант отложен

Это вводит отдельную границу интерпретации Minecraft metadata и меняет способ подготовки набора ресурсов перед verification/download
flow

Для первого подтвержденного сценария подготовленный манифест явно объявляет необходимые ресурсы

---

## Последствия

Файл индекса становится проверяемым и восстанавливаемым ресурсом без новой launcher operation

Значения asset-related launch variables имеют определённые источники и не дублируются в `LaunchInfo`

Существующие манифесты без метадаты файла индекса остаются совместимыми

Подготовка манифеста должна обеспечить согласованность файла индекса и списка объявленных asset objects

Launcher проверяет целостность объявленных ресурсов, но не подтверждает полноту этого списка относительно содержимого файла
индекса

Решение добавляет метадату в assets model и launch planning, но не подтверждает запуск реальной игры до главного меню

---

## Не входит в решение

- Прямой разбор официального Minecraft version JSON как manifest JSON проекта
- Автоматическое преобразование официального asset index в управляемый манифест
- Проверка полноты списка asset objects по содержимому файла индекса
- Изменение политики SHA-256 для проверяемых ресурсов
- Authentication flow и подстановка данных игрока
- Architecture-specific выбор natives
- Отдельные operations, cache policy и cleanup policy для assets
