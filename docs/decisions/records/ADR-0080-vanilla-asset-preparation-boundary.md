# ADR-0080: Определить границу подготовки vanilla asset objects для управляемого манифеста

## Статус

Accepted

> Примечание: решение частично реализовано в итерациях
> `feat(preparer): read and validate vanilla asset index`
> `feat(preparer): verify vanilla asset object bytes`
> `feat(preparer): verify complete vanilla asset object set`
>
> До полного завершения остаются конкретный источник и размещение проверенных байтов,
> определение путей и URI ресурсов, формирование `AssetIndexMetadata` и `AssetEntry`, а также
> сборка окончательного манифеста

---

## Контекст

На момент принятия решения [ADR-0079](ADR-0079-minecraft-asset-index-launch-boundary.md) определяет файл asset index и
объявленные asset objects как ресурсы существующего verification/download flow

`AssetEntry` требует локальный путь, SHA-256, размер и URI каждого объекта

Asset index выбранной vanilla-версии содержит логические имена объектов, SHA-1 и размеры, но не предоставляет SHA-256 и
URI в формате проектного манифеста

Разные логические имена могут ссылаться на один и тот же объект

Ручное перечисление объектов не позволяет надёжно подтвердить полноту подготовленного манифеста относительно индекса

Необходимо определить, кто преобразует метаданные индекса в проверяемые ресурсы до публикации манифеста

---

## Решение

Подготовка asset objects принадлежит стороне публикации управляемого манифеста

Сторона публикации получает файл asset index и сверяет его размер и SHA-1 с метаданными выбранной версии до подготовки
списка объектов

Каждый уникальный хеш объекта из индекса должен иметь соответствующий `AssetEntry` в подготовленном манифесте

Повторные логические имена с одинаковым хешем не создают повторных ресурсов; противоречивые размеры для одного хеша отклоняются

Сторона публикации определяет локальный путь и абсолютный HTTPS URI каждого объекта согласно выбранному источнику ресурсов

До включения объекта в манифест сторона публикации сверяет его байты с размером и SHA-1 из индекса и вычисляет SHA-256 этих
байтов

SHA-256 файла индекса также вычисляется по его проверенным байтам

Невозможность получить или проверять необходимый объект не допускает публикацию манифеста как полный набор ресурсов

Итоговый манифест содержит `AssetIndexMetadata` и список `AssetEntry`, согласованный с уникальными объектами индекса

Подписание выполняется над окончательными байтами подготовленного манифеста согласно [ADR-0072](ADR-0072-managed-manifest-publication-boundary.md)

Launcher проверяет объявленные ресурсы, но не разбирает asset index и не восстанавливает список объектов из него во время
запуска

Решение определяет ответственность стороны публикации, но не закрепляет её за существующим CLI `launcher-publisher` или
новым инструментом

---

## Рассмотренные варианты

### Разбирать asset index внутри launcher

Вариант отложен

Он изменил бы подготовку ресурсов во время launcher lifecycle и потребовал отдельной политики проверки объектов, объявленных
только в загруженном индексе

### Использовать SHA-1 из индекса вместо SHA-256 в runtime-контракте

Вариант отложен

Он потребовал бы изменения общей модели ресурсов и verification/download flow ради одного источника метаданных

Сохранение SHA-256 переносит получение байтов и вычисление хеша на сторону публикации

### Поддерживать список asset objects вручную

Вариант отклонен

При большом количестве объектов ручной список трудно поддерживать и проверять на полноту относительно индекса

---

## Последствия

Подготовленный манифест содержит проверяемый список объектов без нового шага в `LauncherEngine`

Сторона публикации должна иметь доступ к байтам всех уникальных объектов для вычисления SHA-256; для выбранной версии это
существенный объём данных и время подготовки

Полнота списка относительно asset index подтверждается до публикации, но launcher не повторяет эту проверку во время запуска

Подпись подтверждает неизменность опубликованного манифеста относительно доверенного ключа, но сама по себе не устанавливает
происхождение исходных Minecraft metadata

Конкретный способ получения и повторного использования байтов объектов определяется при реализации; это решение не изменяет
runtime-контракт

---

## Не входит в решение

- Прямой разбор официального Minecraft version JSON внутри launcher
- Изменение алгоритма проверки `ResourceEntry`
- Выбор конкретного host для asset objects
- Cache policy и повторное использование загруженных объектов
- Подготовка libraries, natives, logging metadata и launch arguments
- Authentication flow и данные пользовательской сессии
