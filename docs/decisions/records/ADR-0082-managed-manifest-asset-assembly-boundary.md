# ADR-0082: Определить границу сборки управляемого манифеста с подготовленными assets

## Статус

Accepted

> Примечание: решение реализовано в итерации
> `feat(preparer): assemble managed manifest assets from JSON template`

---

## Контекст

На момент принятия решения `launcher-preparer` получает и проверяет vanilla assets и преобразует подготовленные результаты
в `AssetsIndex` согласно [ADR-0080](ADR-0080-vanilla-asset-preparation-boundary.md)

Связка получения индекса, проверки объектов и формирования manifest resources подтверждена интеграционным тестом

Окончательные байты управляемого манифеста пока не формируются

Доменная модель `Manifest` содержит результат runtime selection библиотек и не сохраняет исходные правила выбора, classifiers
и natives metadata в форме публикации

Обратная сериализация этой модели не позволяет восстановить исходный JSON-контракт без потери данных

Необходимо определить способ включения подготовленных assets в манифест до подписания, сохранив остальные разделы независимо
от окружения машины подготовки

---

## Решение

Сборка управляемого манифеста с подготовленными assets принадлежит `launcher-preparer`

Входными данными являются JSON-шаблон манифеста формата проекта и подготовленный `AssetsIndex`

Шаблон не является официальным Minecraft version JSON

Он содержит остальные разделы управляемого манифеста, подготовленные издателем

Шаблон должен содержать один JSON-объект без повторяющихся имен полей

Некорректный или неоднозначный JSON отклоняется

Подготовленный `AssetsIndex` для этого сценария должен содержать метаданные файла индекса

Поля `assets` и `assetIndex` полностью формируются из подготовленного `AssetsIndex`, заменяя прежние значения в шаблоне

Объединение подготовленных объектов с прежним списком `assets` не выполняется

Остальные поля, значения и порядок элементов массивов сохраняются как JSON-данные без runtime selection

Доменная модель `Manifest` не используется как промежуточный источник данных для сборки

Результатом являются окончательные байты JSON в UTF-8

Исходное форматирование и байтовое представление шаблона не сохраняются

`launcher-publisher` подписывает сформированные байты без изменения их содержимого согласно [ADR-0072](ADR-0072-managed-manifest-publication-boundary.md)

Сборка не получает закрытый ключ и не изменяет launcher lifecycle

---

## Рассмотренные варианты

### Сериализовать доменную модель Manifest

Вариант отклонён

Модель содержит результат выбора библиотек для runtime-окружения и не является полным представлением публикуемого JSON-контракта

### Ввести отдельную полную модель публикуемого манифеста

Вариант отложен

Для текущего сценария изменяется только раздел assets

К отдельной модели следует вернуться, если автоматическая подготовка остальных разделов потребует самостоятельного контракта
публикации вместо сохранения данных шаблона

---

## Последствия

Подготовленные assets включаются в манифест без изменения остальных разделов и без зависимости от ОС машины подготовки

Полная замена раздела assets исключает сохранение устаревших объектов из шаблона

Издатель остается ответственным за корректность остальных разделов и их соответствие выбранной версии игры

Структурная проверка JSON и подготовка assets сами по себе не подтверждают корректность client artifact, libraries или
launch arguments

Сериализация изменяет байты шаблона, поэтому подписывается только результат сборки

Повторное преобразование JSON после подписания не допускается

Сборка манифеста сама по себе не подтверждает доступность опубликованных ресурсов или запуск реального Minecraft

---

## Не входит в решение

- Автоматическое преобразование официального Minecraft version JSON
- Подготовка client artifact, libraries, natives и launch arguments
- Authentication flow и данные пользовательской сессии
- CLI и политика записи результирующего файла
- Изменение механизма подписания и хранения ключей
- Выбор хостинга и публикация ресурсов
- Новые launcher operations
