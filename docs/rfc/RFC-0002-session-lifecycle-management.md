# RFC-0002 Session Lifecycle Management

## Статус

Draft

## Цель

Обеспечить безопасное управление жизненным циклом пользовательской сессии в лаунчере

### Решение должно гарантировать:

- Единственную активную сессию для одного профиля
- Корректную работу в многопоточной среде
- Безопасный Logout
- Отсутствие гонок (Race Condition)
- Возможность масштабирования механизма авторизации без изменения клиентского кода

# Термины

## Session

Содержит:
- Профиль
- Токен
- Время создания

Не содержит:
- Сетевой логики
- Проверки доступа
- UI

## SessionManager

Отвечает исключительно за жизненный цикл Session

Может:
- Открыть новую Session
- Закрыть Session
- Предоставить временный доступ

Не отвечает:
- За авторизацию
- За HTTP
- За Refresh Token

## SessionHandle

- Временный объект владения Session
- Используется во время выполнения операций
- После завершения операции освобождается

## AuthenticationProvider

- Создает новую Session
- Не хранит ее
- Передает SessionManager

### Причина

Для поддержания принципа неизменяемости immutability

## Инварианты

|-1

В системе одновременно существует не более одной активной Session для одного профиля

-|2

Session является неизменяемым объектом

-|3

После Logout новые операции не могут получить Session

-|4

Операция, уже получившая SessionHandle, самостоятельно завершает свою работу в соответствии с политикой отмены

-|5

Замена Session всегда выполняется атомарно

## Logout Policy

При выходе пользователя система не отменяет уже выполняющиеся операции принудительно

Используется политика Graceful Completion

Правила:
- Новые операции не могут быть запущены
- Активные операции получают возможность завершиться
- После завершения последней операции Session освобождается
- Только после освобождения Session пользователь может начать новую авторизацию

Причины:
- Отсутствует частично выполненное состояние
- Упрощается обработка ошибок
- Уменьшается вероятность повреждения данных
- Жизненный цикл становится полностью детерминированным
