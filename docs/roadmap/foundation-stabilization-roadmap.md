# Путь стабилизации фундамента

## Цель

Устранить подтверждённые пробелы существующего lifecycle, тестовой инфраструктуры и автоматических проверок до дальнейшего
расширения подготовки запуска

Подготовка vanilla artifacts и развитие технического запуска Minecraft приостановлены до выполнения условий завершения
стабилизации

---

## Текущий план

- Усилить architecture checks согласно существующим модульным границам
- Выделить подтверждённые повторы тестовой инфраструктуры без изменения наблюдаемого поведения сценариев
- Определить и реализовать сетевые deadline и ограничение объема загружаемых данных для подтвержденных внешних границ
- Синхронизировать документацию и провести итоговую повторную ревизию

---

## Выполнено

- Проведена статическая ревизия модульных границ, process boundary, сетевых adapters, quality gate и тестовой инфраструктуры
- Зафиксированы подтверждённые пробелы и приостановлено дальнейшее расширение подготовки запуска
- Устранены непрочитанные stdout и stderr игрового процесса; поведение подтверждено regression tests
- Ограничены время выполнения и объем вывода Java version probe, добавлены bounded cleanup и диагностика отказов
- Process boundary изменения подтверждены локальными проверками и CI на Windows и Linux
- Исправлена проверка многострочных пустых catch blocks, включая блоки только с комментариями; добавлено regression coverage
- Вторичные ошибки cleanup и diagnostic reporting сохраняются как suppressed exceptions без подмены исходного отказа
- Добавлены тесты buildSrc и их явное выполнение в CI на Windows и Linux
- Усилены import-based architecture checks для launcher-core с сохранением допустимых контрактных зависимостей
- Усилены import-based architecture checks для launcher-ui без расширения существующих allowlists
- Добавлено regression coverage для parsing imports и подключения проверок к чтению исходных файлов
- Выделена общая test-only поддержка разбора Java imports согласно [ADR-0083](../decisions/records/ADR-0083-architecture-test-support-boundary.md)
- Проверки launcher-core и launcher-ui переведены на общий parser без изменения правил; добавлены самостоятельные тесты
  контракта parser и модели import
- Добавлена import-based проверка запрета UI и JavaFX imports в launcher-app на основе общего parser
- Добавлены regression tests для правил launcher-app, чтения исходных файлов и диагностики ошибок проверки
- Выделена общая файловая поддержка architecture checks согласно [ADR-0084](../decisions/records/ADR-0084-architecture-source-inspection-boundary.md);
  добавлены самостоятельные regression tests
- Проверки launcher-core, launcher-ui и launcher-app переведены на общую файловую поддержку с сохранением модульных правил
  и существующих regression-сценариев
- В тестах launcher-preparer выделены общий расчет SHA-1/SHA-256 и поток с раздельным наблюдением вызова и успешного
  завершения `close()`
- Добавлены самостоятельные regression tests тестовой поддержки; существующие сценарии подготовки assets и специализированные
  потоки для проверки ошибок чтения и ограничения объема сохранены

Перенаправление вывода не вводит файловое логирование и не гарантирует доступность диагностики при запуске GUI без консоли

Статическая ревизия не заменяет выполнение тестов, CI или независимую проверку безопасности

---

## В работе

- Подтвержден повтор подготовки fake Java executable в launcher-app и launcher-ui
- Следующий шаг — определить владельца общей test-only поддержки этого сценария без изменения production-зависимостей
- HTTP fixtures остаются предметом ревизии: различия управления ответами, синхронизации и lifecycle требуют отдельной оценки
  перед выделением общей части

---

## Условия завершения

- Каждый пункт текущего плана завершен и подтвержден либо явно пересогласован
- Regression tests подтверждают исправление обнаруженных проблем
- Проверки внешних процессов имеют ограниченное ожидание и cleanup при отказе
- qualityCheck и релевантные тесты проходят
- Полный CI проходит на Windows и Linux
- Документация соответствует реализованному поведению
- Итоговая ревизия подтверждает отсутствие незакрытых блокирующих пробелов в согласованном scope

---

## Правило развития

Пункт переносится в выполнено после review и подтвержденных проверок, а не после появления реализации

Roadmap обновляется после завершенных инженерных этапов и не используется как журнал отдельных правок

Подтвержденные пробелы не переносятся в отложенные направления без отдельного согласования
